# Companion drafts and reading position

The editor is separate from sent conversation records. `Session::set_companion_editor` stages a photo's `EditorState` without storage I/O; normal persistence, retries and close flush every staged photo, including photos with no AI history. `companion_dirty_editors` exposes the complete pending list. Drafts never enter model history until a successful local submission appends its immutable request record. Stopping or failing restores only that job's captured request if no later authored draft superseded it; restoration never submits.

Editor metadata lives at `companion/v2/photos/<PhotoId>/editor.json`, outside conversation epochs and HEAD graphs. Its fixed header references a content-addressed UTF-8 draft payload. Loading uses 128 KiB reads, without a draft-size quota or loading conversation records. Normal saves reuse the immutable content object; after a diagnosed payload read error, newly authored text rebuilds that object before saving. The content object is committed before the editor header; failed saves retain the prior visible draft and the new dirty overlay. An error after atomic rename remains retryable. Only obsolete draft payloads are removed after a successful header commit. A corrupt inner conversation does not prevent independent editor loading or saving. An unknown outer root blocks writes; a legacy root retains dirty overlays until migration completes.

The UI scopes draft, TextEdit identity, message ScrollArea identity and reading position by runtime library generation and PhotoId. The independent header also stores the bounded history page cursor (record and fragment byte offset), conversation epoch/count, pixel offset and tail-follow state. Optional fields preserve existing editor headers. Restoring the saved page precedes restoring its pixels; a pending or stale page cannot consume that position. Explicit navigation survives a photo switch before its read completes. Reaching the bottom of an older page does not enable tail following; a saved final fragment remains selected on reopen until new history actually arrives. User scrolling upward turns off tail following; photo/tool switching restores that photo's reading offset and draft. Saved inactive editor buffers are reloadable; ordinary inactive buffers have a 16-entry/2 MiB target, with active tasks and unsaved drafts protected from eviction. Switching photos replaces the visible text buffer so a past large draft does not retain its capacity in another photo.

The first cancellation/consent feedback frame stages only in-memory buffers. Switching to a cold photo during that frame temporarily disables its composer and displays a localized loading state, without showing the prior photo's draft or reading storage. The following frame loads the selected photo normally. An unreadable draft keeps its existing persisted content during reading-only changes; its fallback empty buffer becomes saveable only after the user authors replacement input or restores a newly submitted request.

Follow-on integration: conversation deletion must preserve editor metadata/draft payloads; graph retirement must not collect these independently referenced files. Migration must leave staged editor overlays intact and flush them after activation. Normal library/exit paths call `before_library_change`, which stages restored/visible buffers before normal Session persistence; UX15 owns unified cancellation-before-save ordering and every shutdown entrypoint. Historical comparison must preserve these current-photo buffers and suppress submission controls. Rich prose rendering can extend this same preserved page/scroll position.
